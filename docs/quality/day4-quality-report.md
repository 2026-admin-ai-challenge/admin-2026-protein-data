## ③ 대처 방안 (권장)

아래는 품질 담당의 권장안이다. 최종 결정은 데이터 생성 담당(하태영)과 운영진이 한다.

데이터를 다시 만들 때마다 분할이 섞이고 모델도 다시 학습해야 하므로, **필요한 결정을 모두 끝낸 뒤 한 번만 다시 만드는 것**을 권한다.

```
① 분할 고정 결정 (N-04)  →  ② 고칠 것 확정 (N-02 · N-03 · D-02) + 공개 통계 확인 (N-05)
→  ③ 한 번에 반영해 재생성  →  ④ 같은 양식으로 재점검
```

| 순서 | 문제 | 권장 대처 | 담당 | 중요도 | 이유 |
| --- | --- | --- | --- | --- | --- |
| ① | N-04 분할 흔들림 | 지금 분할(`cb2f530`)을 원본 domain별 학습/평가 배정표로 저장하고, 재생성 때 그 표를 따르도록 수정 | 운영진 결정 → 하태영 | **높음** | 이걸 먼저 해야 ②를 반영해도 평가 문제가 다시 섞이지 않는다 |
| ② | N-03 서열 겹침 (평가 30개) | 평가 쪽 30개를 제외 목록에 추가 | 하태영 | **높음** | 평가 문제의 답이 학습 데이터에 사실상 있음. 평가의 0.6%라 손실이 작다 |
| ② | N-02 모양 섞임 (33개 구조) | 제외 목록에 추가 (사유 P-30) | 하태영 | 중간 | Day 3에서 같은 문제의 평가 8개를 제외했으므로 같은 기준 적용 |
| ② | D-02 붙어 있는데 끊김 | 원본의 C–N 결합으로 연결을 판단하도록 생성 코드 변경. 이번에 못 하면 문서 규칙 유지 + 한계로 기록 | 하태영 (팀 동의) | 중간 | Day 3 D-01과 같은 논리. 다만 코드 변경이 커서 다음 버전으로 미뤄도 된다 |
| ② | N-05 공개 통계 | 운영진에게 의도한 공개인지 확인. 실수면 통계를 학습 데이터만으로 계산 | 운영진 확인 → 하태영 | 낮음 | 평가 분포는 학습 × 0.25로도 거의 짐작할 수 있어 새로 새는 정보가 적다 |
| — | 미확인 8개 구조 | 이번에는 그대로 두고 미확인으로 기록 | 김민준 | 낮음 | 현재 RCSB 파일과 CATH 파일이 달라 판단 근거가 없다 |
| ④ | 재점검 | `day4-quality-template.md`로 학습·평가 전수 점검 | 김민준 | — | 수정이 새 문제를 만들지 않았는지 확인 (Day 5 업무) |

### 대처할 때 주의할 점

- **분할을 고정한 뒤 샘플을 빼면 평가 비율이 20%에서 조금 어긋난다.** N-03의 30개를 빼면 평가가 5,384개에서 5,354개가 된다. 작은 클래스는 평가 수가 줄어 점수가 더 흔들릴 수 있으므로, 제외 후 클래스별 평가 수를 함께 확인한다.
- **분할을 고정하면 모델은 한 번만 다시 학습하면 된다.** PR #6 · #8의 모델은 이전 버전(`797d114`)으로 학습해서 지금 평가 샘플 1,194개를 학습에 썼다. 새 버전으로 다시 학습해야 한다.
- **N-03의 30개는 하한선이다.** 빈칸(삽입·삭제)을 고려하지 않는 단순 비교로 찾았다.

샘플 ID는 `cb2f530` 기준이다. 제외 목록에 넣을 원본 domain 이름은 문서에 적지 않았으니 김민준에게 문의.

### E-03 끊긴 자리의 실제 결합 (D-02)

C-12에서 번호 규칙으로 끊긴 자리마다 원본에서 앞 잔기 C와 뒤 잔기 N 사이 거리를 쟀다. 펩타이드 결합이면 약 1.33Å이다.

| 끊긴 이유 | 학습: 실제 결합 / 전체 | 평가: 실제 결합 / 전체 |
| --- | --- | --- |
| 번호 건너뜀 | 458 / 592 | 95 / 129 |
| 번호 역행 | 15 / 15 | 2 / 2 |
| 삽입 코드 역순 (`99A → 99`) | 5 / 5 | — |
| 삽입 코드 건너뜀 (`166 → 166B`) | 3 / 3 | 8 / 8 |

결합이 아닌 곳(학습 134, 평가 34)은 실제로 사슬이 끊긴 자리라 지금 규칙이 맞다. 떨어진 조각(학습 60, 평가 17)은 원래 사슬에서 이웃이 아니라 대상에서 뺐다.

Day 1 보고서도 이 묶음을 "사슬은 실제로 이어져 있지만 번호가 연속이 아니라 문서 규칙대로 끊김"으로 적었다. Day 3에서 `208 → 209A`를 이어진 것으로 고친 근거(실제 결합)를 그대로 적용하면 이 자리들도 이어진 것이 된다. 다만 PR #11의 문서는 번호 건너뜀 · 역행을 끊김으로 명시했으므로, 버그가 아니라 규칙을 정할 문제다.

### E-05 분할 변화 (N-04)

| 비교 | 학습 → 평가 | 평가 → 학습 | 평가 유지 |
| --- | ---: | ---: | --- |
| `44e28e4` → `797d114` (PR #5) | 147 | 147 | 5,240 / 5,387 |
| `797d114` → `cb2f530` (PR #11) | 1,194 | 1,188 | 4,190 / 5,384 |

PR #11에서 평가가 바뀐 클래스는 3.30(833개 중 51%)과 3.40(1,151개 중 67%)뿐이다. 나머지 18개 클래스는 1% 이하로 바뀌었다. Public/Private가 바뀐 평가 샘플은 유지된 4,190개 중 1,369개, fit/validation이 바뀐 학습 샘플은 3,240개다.

원리: 분할 코드는 클래스마다 묶음을 쪼개지 않고 "평가 목표 개수(20%)에 가장 가깝게 맞는 묶음 조합"을 고른다. 샘플이 1개만 빠져도 목표 개수가 바뀌어 전혀 다른 조합이 뽑힐 수 있다. 같은 코드로 만든 예제(묶음 12개, 샘플 118개)에서 학습 쪽 샘플 1개를 빼자 평가 묶음이 통째로 바뀌었다.
