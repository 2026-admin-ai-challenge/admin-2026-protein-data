# 품질 보고서 양식 (2차)

데이터를 다시 만들 때마다 같은 순서로 전수 점검하고 결과를 남기는 양식이다. Day 1(결측·중복·불일치), Day 2(비정상 값), Day 3(수정 확인·평가 데이터·추가 점검)의 점검을 하나로 묶었다. 원본 데이터는 수정하지 않는다.

이 양식을 채운 보고서는 데이터팀 밖(운영진, 웹사이트팀)도 읽는다. 결론과 할 일을 앞에 두고, 근거는 뒤 절과 세부 문서로 보낸다.

## ① 개요 (점검할 때 채움)

| 항목 | 내용 |
| --- | --- |
| 점검자 | |
| 점검일 | |

## ② 표기 규칙

### 판정 (샘플·지점 단위)

| 판정 | 뜻 |
| --- | --- |
| 오류 (원본 구조) | 원본 실험 구조 자체가 잘못됨. 생성 코드는 그대로 옮김 |
| 오류 (생성 코드) | 데이터를 만드는 코드가 잘못 처리함 |
| 특이하지만 정상 | 단백질이 원래 특이함. 학습·평가에 같은 방식으로 있으면 문제 아님 |
| 미확인 | 아직 판단 근거가 없음 |

### 상태 (문제 단위)

| 상태 | 뜻 |
| --- | --- |
| 해결 | 같은 점검을 다시 돌렸을 때 문제가 나오지 않음 |
| 잔여 | 해당 샘플은 처리됐지만 같은 원인이 남을 수 있음 (한계를 알고 남겨 둠) |
| 수정 필요 | 고칠 근거가 확인됐고 아직 반영되지 않음 |
| 결정 필요 | 고칠지 말지 팀이 정해야 함 |
| 신규 | 이번 점검에서 처음 나온 문제 |

### 기록하지 않는 것

평가 데이터의 정답(label), Public/Private 구분, 원본 domain 이름, 단백질 이름은 어느 문서에도 적지 않는다. 이름만으로 CATH에서 정답을 찾을 수 있다. 필요하면 점검자에게 문의하도록 적는다.

## ⑥ 대처 방안 (권장)

보고서에서는 결론 바로 뒤에 둔다. 최종 결정은 데이터 생성 담당과 운영진이 하므로 "권장"임을 밝힌다.

| 순서 | 문제 | 권장 대처 | 담당 | 중요도 | 이유 |
| --- | --- | --- | --- | --- | --- |
| | | | | 높음 / 중간 / 낮음 | |

- 데이터를 다시 만들어야 하는 대처는 한 번에 모아 반영하도록 순서를 정한다. 다시 만들 때마다 분할과 샘플 ID가 바뀐다.
- 대처할 때 생기는 부작용(비율 변화, 모델 재학습 등)을 함께 적는다.
