## ⑦ 신규 문제 N-01: `21A → 22`를 끊김으로 기록

### 무엇이 바뀌었나

`scripts/structure_dataset.py`의 `consecutive()`는 원본 번호를 보고 두 아미노산이 바로 이웃인지 판단한다. 이 판단이 segment_index("이어진 뼈대 구간")가 된다. PR #5에서 "번호 +1"일 때의 조건이 바뀌었다.

```python
# 수정 전 (1차 데이터)
(number_b == number_a + 1 and not insertion_b)            # 뒤 번호에 알파벳이 없으면 이어짐
# 수정 후 (PR #5)
(number_b == number_a + 1 and insertion_b == insertion_a)  # 앞뒤 알파벳이 같으면 이어짐
```

| 원본 번호 | 실제 | 수정 전 | 수정 후 |
| --- | --- | --- | --- |
| `21 → 22` | 이어짐 | 이어짐 | 이어짐 |
| `4P → 5P` | 이어짐 | 끊김 (1차 버그) | 이어짐 |
| `21A → 22` | 이어짐 | 이어짐 | **끊김 (N-01)** |
| `208 → 209A` | 이어짐 | 끊김 | 끊김 (D-01) |

기존 조건에 새 조건을 **더해야** 했는데 **바꿔서**, 1차 버그는 고쳐졌지만 원래 맞던 경우가 틀리게 됐다. 1차 보고서의 고치는 방향("번호가 +1이고 앞뒤 알파벳이 같으면 연속으로 인정")에 "기존 조건에 더해서"라는 말이 없어 대체로도 읽힐 여지가 있었다.

### 판별 방법

1. C-12를 새 데이터에 돌렸을 때 "번호는 이어지는데 끊김" 유형이 새로 나왔다. 1차 데이터에서는 0곳이었다.
2. 원본과 대조하니 모두 `알파벳 붙은 번호 → 다음 맨 번호` 패턴이었다.
3. `consecutive(('A', 21, 'A'), ('A', 22, ''))`가 `False`를 돌려주는 것을 코드로 재현했다.

| 실제 연결 여부 | Cα 간격 2.93 ~ 3.9Å로 모두 정상 연결 |
| 많이 걸리는 클래스 | 2.40 (42개), 2.60 (18개), 3.40 (14개). 항체처럼 `82A, 82B, 82C, 83` 식의 삽입 번호를 쓰는 단백질 |

### 고치는 방향

D-01과 같은 줄이라 ⑧의 수정 지시 한 번으로 함께 해결된다. `21A → 22`가 이어지는지 확인하는 테스트를 넣어야 같은 실수가 반복되지 않는다.

## ⑧ 1차 판단 보류 항목 D-01: `208 → 209A` (수정 필요)

### 1차 기록

Day 1 보고서 79번째 줄: "삽입 코드 경계(`208 → 209A`, 31곳)는 번호 체계를 어떻게 읽느냐에 따라 연속으로 볼 여지가 있다. 규칙을 그대로 둘지는 팀이 판단할 사항이다." PR #5 전후로 바뀌지 않았다. 이번 재점검에서 원본을 직접 재서 판단 근거를 확인했다.

### 판별 방법

원본 PDB에서 끊긴 두 아미노산 사이를 직접 쟀다(`day3_boundary.py`).

| 확인 항목 | 뜻 |
| --- | --- |
| 앞 잔기 C ↔ 뒤 잔기 N 거리 | 두 아미노산이 화학적으로 결합(펩타이드 결합)했으면 약 1.33Å |
| Cα 간격 | 이웃 아미노산이면 약 3.8Å |
| REMARK 465 | 실험에서 안 보여 빠진 아미노산 기록. 사이에 기록이 있으면 실제로 빠진 것 |

번호만 건너뛴 것처럼 보일 뿐, 실제로는 바로 붙어 있는 이웃이다. 비슷한 단백질과 번호를 맞추려고 "기준 번호"를 쓰는데, 이 단백질에는 209번 자리가 없고 대신 다른 아미노산이 끼어 있어 `209A`가 붙은 경우다.

### 문서 기준

`docs/structure-format.md` 14번째 줄은 segment_index를 "Continuous backbone segment"(이어진 뼈대 구간)로 정의하고, 끊는 조건으로 "numbering/chain discontinuity"(번호·사슬이 이어지지 않을 때)를 든다. `208 → 209A`는 정의(실제로 이어짐)로는 이어진 구간이고, 끊는 조건을 글자 그대로 읽으면 끊김이다. 1차는 끊는 조건만 보고 판단을 보류했다.

### 판정

**38곳 모두 실제로 결합된 이웃이므로 이어진 것이 맞다.** 지금의 끊김 기록은 segment_index의 정의와 어긋난다. 끊는 조건의 "numbering discontinuity"가 삽입 코드 알파벳까지 보도록 해석된 것이 원인이다.

### 수정 지시

**① 코드:** `scripts/structure_dataset.py`의 `consecutive()` 30번째 줄을 고친다. 번호가 +1이면 삽입 코드 알파벳과 상관없이 이어진 것으로 본다. 반복문의 거리 4.5Å 조건은 그대로 두므로, 번호만 이어지고 실제로 떨어진 경우는 계속 끊긴다. N-01도 이 한 줄로 함께 해결된다.

```python
# 현재 (PR #5)
return ((number_b == number_a + 1 and insertion_b == insertion_a) or
        (number_b == number_a and insertion_b and
         ord(insertion_b) == (ord(insertion_a) + 1 if insertion_a else ord("A"))))

# 수정
return ((number_b == number_a + 1) or
        (number_b == number_a and insertion_b and
         ord(insertion_b) == (ord(insertion_a) + 1 if insertion_a else ord("A"))))
```

**② 테스트:** `tests/test_structures.py`에 삽입 코드 경우를 모두 확인하는 테스트를 추가한다.

```python
from scripts.structure_dataset import consecutive

@pytest.mark.parametrize("a, b", [
    (("A", 208, ""), ("A", 209, "A")),   # D-01
    (("A", 21, "A"), ("A", 22, "")),     # N-01
    (("A", 4, "P"), ("A", 5, "P")),      # 1차 버그
    (("A", 21, ""), ("A", 21, "A")),
    (("A", 21, "A"), ("A", 21, "B")),
])
def test_insertion_codes_are_continuous(a, b):
    assert consecutive(a, b)
```

**③ 문서:** `docs/structure-format.md` 14번째 줄의 끊는 조건을 코드와 같은 뜻으로 고친다.

| | 내용 |

| 현재 | Continuous backbone segment; breaks on missing Cα, numbering/chain discontinuity or Cα step >4.5 Å |
| 수정 | Continuous backbone segment; breaks on missing Cα, chain change, PDB residue-number gap or reversal, or Cα step >4.5 Å. Insertion codes do not break a segment (208 → 209A, 21A → 22 and 21 → 21A are continuous) |
